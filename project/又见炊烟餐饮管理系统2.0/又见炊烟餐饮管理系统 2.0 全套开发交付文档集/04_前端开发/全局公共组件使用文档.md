# 全局公共组件使用文档

> 适用：`frontend_v3/src/components/**`  
> 技术栈：Vue 3.4 + Vite 5 + Element Plus + Pinia  
> 设计风格：徽派雅致配色（深绿 #1a3a2a / #2D4A3E + 金色 #C4A35A + 暖米色 #F5F0E8 / #FAF8F5）  
> 维护：Trae（TRAE-BOT）  
> 更新：2026-08-02

---

## 0. 文档说明

本文档汇总又见炊烟餐饮管理系统 2.0 前端工程 `frontend_v3/src/components/` 目录下全部全局公共组件，逐一说明组件用途、Props、Events、Slots 及使用示例代码。所有组件均采用 Vue 3 `<script setup>` 语法编写，与 Element Plus 组件库配合使用。组件按业务场景分为三类：

1. **业务壳层组件**：`BizPageWrapper` 用于业务页面整体骨架。
2. **业务弹窗组件**：`BookingDialog`、`DishOrderDialog` 用于核心业务交互。
3. **打印与智能助理组件**：`PrintButton`、`PrintPreview`、`AIChatFloat` 用于辅助能力集成。

引用方式统一使用 `@/components/xxx.vue` 路径别名（已在 `vite.config.js` 配置 `@` 指向 `src`）。组件文件按 `PascalCase.vue` 命名，使用时建议在模板中以 `PascalCase` 形式书写标签，便于与原生 HTML 元素区分。

设计色彩约定：

| 色名 | 色值 | 用途 |
|------|------|------|
| 主深绿 | `#2D4A3E` / `#1a3a2a` | 头部底色、按钮主色、强调文字 |
| 金色 | `#C4A35A` | 分隔线、标签、副标题、品牌点缀 |
| 暖米色 | `#FAF8F5` / `#F5F0E8` | 弹窗底色、卡片背景、低饱和填充 |
| 灰文字 | `#888` / `oklch(0.52 0.02 150)` | 辅助标签、占位文字 |

## 1. BizPageWrapper 业务页面外壳

### 1.1 组件信息

| 项 | 内容 |
|---|---|
| 组件名 | `BizPageWrapper` |
| 文件路径 | `frontend_v3/src/components/BizPageWrapper.vue` |
| 用途 | 业务模块页面的统一外壳，提供页面标题、副标题、空状态展示。当 `hasContent` 为 `false` 时展示空状态卡片；为 `true` 时展示插槽内容。常用于 Dashboard 后台各业务页面的空/有内容状态切换。 |

### 1.2 Props

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `title` | String | `''` | 页面主标题，渲染为 `<h2>` |
| `subtitle` | String | `''` | 页面副标题，渲染为 `<p class="page-desc">` |
| `icon` | String | `''` | 空状态展示的图标（emoji 或字符，直接渲染文本） |
| `emptyTitle` | String | `'暂无数据'` | 空状态主文案 |
| `emptyDesc` | String | `'此模块暂无内容'` | 空状态副文案 |
| `hasContent` | Boolean | `false` | 是否有内容。为 `true` 时渲染默认插槽，为 `false` 时渲染空状态块 |

### 1.3 Events

无。

### 1.4 Slots

| 插槽名 | 说明 |
|--------|------|
| `default` | 默认插槽。仅当 `hasContent` 为 `true` 时渲染。用于放置页面真实业务内容。 |

### 1.5 使用示例

```vue
<template>
  <BizPageWrapper
    title="采购管理"
    subtitle="采购单 · Purchase Management"
    icon="〔采购〕"
    empty-title="暂无采购单"
    empty-desc="当前门店本月尚未创建采购单"
    :has-content="list.length > 0"
  >
    <PurchaseList :data="list" />
  </BizPageWrapper>
</template>

<script setup>
import { ref } from 'vue'
import BizPageWrapper from '@/components/BizPageWrapper.vue'
import PurchaseList from './PurchaseList.vue'

const list = ref([])
</script>
```

### 1.6 实现要点

- 头部使用 `el-tag` 区分有内容（success 实心圆角）与无内容（info 描边圆角）状态。
- 无内容时整体加 `grayscale(0.3)` 与 `opacity: 0.85` 滤镜，营造"灰化"视觉。
- 有内容时背景使用极淡紫色线性渐变 `linear-gradient(135deg, rgba(124,58,237,0.03), rgba(124,58,237,0.01))`，与主品牌色形成层次。

## 2. BookingDialog 预订弹窗

### 2.1 组件信息

| 项 | 内容 |
|---|---|
| 组件名 | `BookingDialog` |
| 文件路径 | `frontend_v3/src/components/BookingDialog.vue` |
| 用途 | 宴会预订的核心业务弹窗。支持新建预订、编辑预订、查看预订详情三种模式，包含预订时间、客户历史、菜单、变更记录四个标签页，集成客户自动补全、手机号查历史、桌台配置、点菜下单、打印确认单/桌签/取消单、一键复制通知文案等完整能力。 |

### 2.2 Props

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `modelValue` | Boolean | `false` | 弹窗显隐（v-model 双向绑定） |
| `date` | String | `''` | 预订日期（YYYY-MM-DD）。新建时作为默认日期。 |
| `tableId` | Number | `undefined` | 单选桌台 ID |
| `tableNumber` | String | `undefined` | 单选桌台编号 |
| `tableName` | String | `undefined` | 单选桌台名称 |
| `tableIds` | Array | `undefined` | 多选桌台 ID 数组（与 `tableId` 互斥，优先使用） |
| `tableNames` | Array | `undefined` | 多选桌台名称数组，与 `tableIds` 配合使用 |
| `booking` | Object | `undefined` | 编辑模式时传入预订对象。包含 `id`/`bookingId`/`booking_id`/`order_no` 之一即可触发详情拉取；含 `_noEdit=true` 强制只读；含 `_editMode=true` 进入编辑模式；含 `_goDishTab=true` 打开后跳到菜单 Tab。 |

### 2.3 Events

| 事件名 | 回调参数 | 说明 |
|--------|---------|------|
| `update:modelValue` | `(val: boolean)` | 弹窗显隐变化 |
| `saved` | `(data: object)` | 保存成功后回调，返回后端响应体 |
| `date-change` | `(date: string)` | 用户在弹窗内修改预订日期时触发，供父组件同步刷新桌台看板 |
| `period-change` | `(newMeal, oldMeal, date)` | 用户切换餐别（午餐/晚餐）时触发 |
| `print` | `({ type, data })` | 点击打印按钮时触发，`type` 为 `'confirmation'`/`'table_sign'`/`'cancellation'`，`data` 为打印数据 |

### 2.4 Slots

无显式插槽。弹窗内部通过四个标签页 `basic`/`history`/`menu`/`logs` 组织内容。

### 2.5 defineExpose 暴露方法

父组件可通过 ref 调用以下方法：

| 方法名 | 签名 | 说明 |
|--------|------|------|
| `updateSelectedTables` | `(tables: Array) => boolean` | 桌台看板数据更新后，校验已选桌台是否仍可用。返回 `true` 表示有桌台被占用需提示。 |
| `revertDate` | `(oldDate: string) => void` | 回滚预订日期到旧值 |
| `revertPeriod` | `(oldPeriod: string) => void` | 回滚餐别到旧值，同时重置时段 |
| `getCurrentPeriod` | `() => string` | 获取当前餐别（'lunch'/'dinner'） |

### 2.6 使用示例

```vue
<template>
  <BookingDialog
    ref="bookingDialogRef"
    v-model="dialogVisible"
    :date="currentDate"
    :table-ids="selectedTableIds"
    :table-names="selectedTableNames"
    :booking="editingBooking"
    @saved="onSaved"
    @date-change="onDateChange"
    @period-change="onPeriodChange"
    @print="onPrint"
  />
</template>

<script setup>
import { ref } from 'vue'
import BookingDialog from '@/components/BookingDialog.vue'

const dialogVisible = ref(false)
const bookingDialogRef = ref(null)
const selectedTableIds = ref([1, 2])
const selectedTableNames = ref(['A01', 'A02'])
const editingBooking = ref(null)
const currentDate = ref('2026-08-02')

function onSaved(data) {
  console.log('保存成功', data)
}
function onDateChange(date) {
  // 重新拉取该日期的桌台占用情况
}
function onPeriodChange(newMeal, oldMeal, date) {
  // 餐别变更，刷新桌台
}
function onPrint({ type, data }) {
  // type: 'confirmation' | 'table_sign' | 'cancellation'
  console.log('打印', type, data)
}
</script>
```

### 2.7 实现要点

- 弹窗打开时若传入 `booking` 对象且包含预订 ID，会调用 `getBookingDetail(bookingId)` 拉取最新详情，失败时回退使用父组件传入的 `booking` 对象填充表单。
- 手机号失焦自动校验格式 `/^1[3-9]\d{9}$/`，并查询客户历史预订，根据到店次数提示"回头客/VIP"。
- 保存成功后会自动调用 `submitLocalDishesToBackend` 将本地点菜数据批量提交到后端 `/api/bookings/{id}/dishes/batch`。
- 表单校验在 `validateBooking` 函数中，校验失败使用 `ElMessageBox.alert` 列出所有错误项。
- 双击弹窗主体区域可从只读模式切换到编辑模式（受 `noEdit` 控制）。

## 3. DishOrderDialog 点菜弹窗

### 3.1 组件信息

| 项 | 内容 |
|---|---|
| 组件名 | `DishOrderDialog` |
| 文件路径 | `frontend_v3/src/components/DishOrderDialog.vue` |
| 用途 | 点菜业务弹窗。支持零点菜肴（按分类浏览+搜索添加）与宴会菜肴（套餐整体加入）两种来源模式，左侧菜品网格 + 右侧购物车实时联动，菜品数据持久化到 `menuStore`（按 date/period/tableName 维度存储）。 |

### 3.2 Props

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `visible` | Boolean | `false` | 弹窗显隐（使用 `update:visible` 事件双向绑定） |
| `date` | String | `''` | 预订日期，作为 `menuStore` 的存储键之一 |
| `period` | String | `''` | 餐别时段（含 `lunch`/`午` 视为午餐，否则晚餐） |
| `tableName` | String | `''` | 桌台名称，作为 `menuStore` 的存储键之一 |

### 3.3 Events

| 事件名 | 回调参数 | 说明 |
|--------|---------|------|
| `update:visible` | `(val: boolean)` | 弹窗显隐变化 |
| `confirmed` | `()` | 用户点击"确认"按钮且购物车非空时触发 |

### 3.4 Slots

无显式插槽。弹窗内部分为左侧菜品区（含分类标签 + 菜品网格/套餐网格）和右侧购物车区。

### 3.5 使用示例

```vue
<template>
  <DishOrderDialog
    v-if="dishVisible"
    v-model:visible="dishVisible"
    :date="bookingDate"
    :period="bookingTime"
    :table-name="tableName"
    @confirmed="onDishConfirmed"
  />
</template>

<script setup>
import { ref } from 'vue'
import DishOrderDialog from '@/components/DishOrderDialog.vue'

const dishVisible = ref(false)
const bookingDate = ref('2026-08-02')
const bookingTime = ref('18:00:00')
const tableName = ref('A01')

function onDishConfirmed() {
  console.log('点菜已确认')
}
</script>
```

### 3.6 实现要点

- 弹窗 `@opened` 时触发 `loadAll`，并行加载菜品列表（`getDishes({ usageType: 'a_la_carte' })`）、分类列表（`getCategories()`）、套餐列表（`getPackages()`）。
- 菜品数据兼容多字段：`dishId`/`id`、`dishName`/`name`、`salePrice`/`price`、`dishCategoryId`/`categoryId` 等，适配不同接口返回。
- 购物车数据通过 `menuStore` 工具函数管理：`addDishToOrder`、`updateDishQty`、`removeDishFromOrder`、`clearTableOrders`，存储键格式为 `getOrderKey(date, period, tableName)`。
- 套餐加入菜单时遍历 `pkg.dishes`/`packageDishes`/`items` 任一字段，逐道加入购物车。
- 清空操作使用 `ElMessageBox.confirm` 二次确认。
- 菜品标签按 `tag`/`isSignature`/`isPopular` 字段渲染：招牌（金色）、热销（红色）、新品（绿色）。

## 4. AIChatFloat AI 浮动助理

### 4.1 组件信息

| 项 | 内容 |
|---|---|
| 组件名 | `AIChatFloat` |
| 文件路径 | `frontend_v3/src/components/AIChatFloat.vue` |
| 用途 | 右下角浮动的 AI 智能助理"炊小助"。支持文字对话、图片上传识别、模型切换、对话历史加载、面板拖拽、刷新新话题。无需父组件传入任何 Props，自包含全部逻辑，可直接在全局 Layout 中挂载一次。 |

### 4.2 Props

无。

### 4.3 Events

无。组件内部通过 `fetch` 直接调用后端 AI 接口，不向上抛事件。

### 4.4 Slots

无。

### 4.5 内部接口调用

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/ai/models` | GET | 拉取可用模型列表（chat/vision 两类），挂载时调用一次 |
| `/api/ai/history` | GET | 拉取历史对话记录，面板打开时调用 |
| `/api/ai/history/clear` | POST | 清空后端历史，刷新对话时调用 |
| `/api/ai/chat/completions` | POST | 发送对话，请求体 `{ model, messages, max_tokens }`，兼容 OpenAI 响应格式 |

### 4.6 使用示例

```vue
<template>
  <div class="layout">
    <router-view />
    <AIChatFloat />
  </div>
</template>

<script setup>
import AIChatFloat from '@/components/AIChatFloat.vue'
</script>
```

### 4.7 实现要点

- 触发按钮固定在右下角 `position: fixed; bottom: 24px; right: 24px; z-index: 9999`，初始 `opacity: 0.7`，悬停放大并提亮。
- 面板可拖拽：监听 `mousedown`（限定在 `.chat-header` 区域）/`mousemove`/`mouseup`，位置由 `panelX`/`panelY` 控制，并限制不超出视口。
- 双击面板头部调用 `minimize()` 收起面板。
- 支持图片上传（文件选择 + 粘贴板 `paste` 事件），图片转 base64 预览后随消息发送。
- 语音录制（`MediaRecorder`）和文件上传为占位实现，提示需后端支持。
- 消息文本支持简单的 Markdown 加粗 `**text**` 解析（`formatText` 函数）。
- 模型选择下拉分组：对话模型 + 识图模型，默认空字符串表示"智能路由"。

## 5. PrintPreview 打印预览弹窗

### 5.1 组件信息

| 项 | 内容 |
|---|---|
| 组件名 | `PrintPreview` |
| 文件路径 | `frontend_v3/src/components/PrintPreview.vue` |
| 用途 | 打印预览弹窗（TypeScript `<script setup lang="ts">`）。根据 `type` 渲染三种打印模板：预订确认单（A5）、桌签（A6 竖版）、取消单（A5）。内置 `@media print` 样式，调用 `window.print()` 时自动隐藏弹窗外框，仅打印模板内容。 |

### 5.2 Props

| 参数名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `visible` | boolean | 必填 | 弹窗显隐 |
| `type` | `'confirmation' \| 'table_sign' \| 'cancellation'` | 必填 | 打印模板类型 |
| `data` | `BookingData` | 必填 | 打印数据对象 |

`BookingData` 接口定义：

```ts
interface BookingData {
  booking_id?: string
  booking_date?: string
  booking_time?: string
  customer_name?: string
  customer_phone?: string
  occasion_type?: string
  table_count?: number
  spare_tables?: number
  guest_per_table?: number
  deposit?: string | number
  remark?: string
  booking_status?: string
  created_at?: string
  staff_name?: string
  booking_tables?: Array<{ table_id?: number; table_name?: string; table_number?: string }>
}
```

### 5.3 Events

| 事件名 | 回调参数 | 说明 |
|--------|---------|------|
| `close` | `()` | 弹窗关闭时触发（点击关闭按钮、点击遮罩外的取消按钮、或 `model-value` 变为 false） |

### 5.4 Slots

无。模板内容根据 `type` 条件渲染，无法通过插槽覆盖。

### 5.5 使用示例

```vue
<template>
  <PrintPreview
    :visible="previewVisible"
    :type="printType"
    :data="printData"
    @close="previewVisible = false"
  />
</template>

<script setup lang="ts">
import { ref } from 'vue'
import PrintPreview from '@/components/PrintPreview.vue'

const previewVisible = ref(false)
const printType = ref<'confirmation' | 'table_sign' | 'cancellation'>('confirmation')
const printData = ref({
  booking_id: 'BK20260802001',
  booking_date: '2026-08-02',
  booking_time: '18:00:00',
  customer_name: '张三',
  customer_phone: '138****8888',
  occasion_type: 'wedding',
  table_count: 5,
  spare_tables: 1,
  guest_per_table: 10,
  deposit: 2000,
  booking_tables: [{ table_name: 'A01' }, { table_name: 'A02' }]
})
</script>
```

### 5.6 实现要点

- A5 模板尺寸 `148mm × 210mm`，A6 桌签尺寸 `105mm × 148mm`，符合标准打印纸张。
- 宴席类型映射 `occasionMap` 覆盖 12 种：零点、婚宴、生日宴、订婚宴、满月宴、谢师宴、帮忙酒、乔迁宴、升迁宴、团圆宴、答谢宴、尾牙宴。
- `totalGuests` 计算属性：`(table_count + spare_tables) * guest_per_table`。
- 打印时通过 `@media print` 隐藏 `.no-print`、`.print-toolbar`、`.el-dialog__header`、`.el-dialog__footer`，并强制 `print-color-adjust: exact` 保留背景色。
- `currentDateTime` 计算属性实时生成"打印时间"，格式 `YYYY-MM-DD HH:mm`。

## 7. 组件协作关系

```
BookingDialog (预订弹窗)
  ├── 内嵌 DishOrderDialog (点菜弹窗) ── 读写 menuStore
  ├── 通过 emit('print') 触发父组件 ──> 父组件可挂载 PrintPreview
  └── 或父组件直接挂载 PrintButton ──> 内嵌 PrintPreview

BizPageWrapper (业务外壳)
  └── 包裹业务页面内容，空/有内容状态切换

AIChatFloat (AI助理)
  └── 全局独立挂载，不与其他组件耦合
```

典型业务页面组合示例：

```vue
<template>
  <BizPageWrapper title="预订管理" :has-content="true">
    <Bookings @open-booking="openBooking" />
    <BookingDialog ref="dialogRef" v-model="dialogVisible" :booking="current" @print="onPrint" />
    <PrintPreview :visible="printVisible" :type="printType" :data="printData" @close="printVisible = false" />
  </BizPageWrapper>
  <AIChatFloat />
</template>
```

## 8. 新增组件规范

在 `frontend_v3/src/components/` 下新增组件时，遵循以下规范：

1. **文件命名**：`PascalCase.vue`，如 `OrderFilter.vue`。
2. **组件名导出**：使用 `<script setup>` 时组件名由文件名推导，无需显式 `name` 选项。
3. **Props 定义**：使用 `defineProps` 对象语法，每个 prop 标注类型与默认值；TS 项目可使用泛型语法 `defineProps<{...}>()`。
4. **Events 定义**：使用 `defineEmits` 显式声明事件名，便于父组件类型推导。
5. **样式隔离**：使用 `<style scoped>`；若需覆盖 Element Plus 内部样式（如 `.el-dialog__header`），使用非 scoped 的 `<style>` 块配合自定义类名（如 `.bk-dlg .el-dialog__header`）。
6. **色彩使用**：主色 `#2D4A3E`、点缀 `#C4A35A`、背景 `#FAF8F5`，避免引入新色值；新组件也可使用 `oklch()` 函数表达（与现有组件一致）。
7. **i18n**：业务弹窗内文案使用 `useI18n()` 的 `t()` 函数，键名按模块组织（如 `booking.title`、`menu.search`）。
8. **依赖注入**：组件内部如需调用后端，统一通过 `@/api/xxx` 封装的请求函数，不直接 `fetch`（`AIChatFloat` 因历史原因直接 fetch，新增组件不应仿效）。

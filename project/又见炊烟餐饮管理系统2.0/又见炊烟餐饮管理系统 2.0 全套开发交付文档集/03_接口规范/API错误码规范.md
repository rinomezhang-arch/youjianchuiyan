## 一、错误码结构

### 1.1 错误码格式
```
错误码 = 6位数字
格式：XX YY ZZ
      │  │  │
      │  │  └─ 具体错误序号（00-99）
      │  └─── 模块代码（00-99）
      └────── 错误类型（1-9）
```

### 1.2 错误类型
| 类型 | 含义 | 示例 |
|------|------|------|
| 1xx | 客户端错误（参数校验、认证） | 100001 |
| 2xx | 业务逻辑错误 | 200001 |
| 3xx | 权限错误 | 300001 |
| 4xx | 资源不存在 | 400001 |
| 5xx | 系统内部错误 | 500001 |

## 四、使用规范

### 4.1 后端使用
```java
// 定义错误码枚举
public enum ErrorCode {
    PARAM_INVALID(100001, "参数校验失败"),
    UNAUTHORIZED(100010, "未登录或登录已过期"),
    BOOKING_TIME_EXPIRED(210001, "预订时间已过期"),
    // ...
    ;

    private final Integer code;
    private final String message;
}

// 抛出业务异常
throw new BusinessException(ErrorCode.BOOKING_TIME_EXPIRED);
throw new BusinessException(210003, "该时段桌台已满");
```

### 4.2 前端使用
```javascript
// 统一错误处理
const handleError = (error) => {
    const { code, message } = error.response.data;
    
    switch (code) {
        case 100010:
        case 100011:
        case 100012:
            // 跳转登录页
            router.push('/login');
            break;
        case 300001:
            // 提示无权限
            ElMessage.error('您没有权限执行此操作');
            break;
        default:
            ElMessage.error(message || '系统繁忙，请稍后重试');
    }
};
```

## 五、错误码分配规范

1. **新增错误码必须先在本文档登记**，避免重复
2. **错误码一旦发布，禁止修改含义**，只能废弃新增
3. **废弃的错误码标记为 Deprecated**，保留至少一个版本
4. **错误码必须配套中英文说明**

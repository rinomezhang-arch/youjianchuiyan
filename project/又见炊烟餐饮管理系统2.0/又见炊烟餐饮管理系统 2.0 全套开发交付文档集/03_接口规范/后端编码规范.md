## 一、项目结构规范

### 1.1 分层结构
```
com.youjian.banquet
├── controller/          # 控制层：接收请求，返回响应
├── service/             # 业务层：核心业务逻辑
│   └── impl/            # 业务层实现
├── repository/          # 数据访问层：数据库操作
├── entity/              # 实体类：对应数据库表
├── dto/                 # 数据传输对象：接口入参
├── vo/                  # 视图对象：接口出参
├── mapper/              # MyBatis Mapper接口
├── config/              # 配置类
├── aspect/              # 切面类
├── exception/           # 异常类
├── util/                # 工具类
└── constant/            # 常量类
```

## 二、Controller 规范

### 2.1 基本结构
```java
@RestController
@RequestMapping("/api/bookings")
@Tag(name = "预订管理", description = "预订相关接口")
public class BookingController {

    @Autowired
    private BookingService bookingService;

    @PostMapping
    @Operation(summary = "创建预订")
    public Result<BookingVO> create(@RequestBody @Valid BookingCreateDTO dto) {
        return Result.success(bookingService.create(dto));
    }

    @GetMapping("/{id}")
    @Operation(summary = "获取预订详情")
    public Result<BookingVO> getById(@PathVariable Long id) {
        return Result.success(bookingService.getById(id));
    }
}
```

### 2.2 规范要求
1. **必须使用 `@Valid` 校验入参**
2. **必须使用 `@Operation` 标注接口说明**（Swagger文档）
3. **统一返回 `Result<T>` 包装类**
4. **禁止在 Controller 写业务逻辑**，只调用 Service
5. **路径命名使用复数**：`/bookings` 不是 `/booking`

## 三、Service 规范

### 3.1 基本结构
```java
@Service
@Slf4j
public class BookingServiceImpl implements BookingService {

    @Autowired
    private BookingRepository bookingRepository;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public BookingVO create(BookingCreateDTO dto) {
        // 1. 业务校验
        validateBookingTime(dto.getBookingTime());

        // 2. 业务逻辑
        BookingMaster entity = convertToEntity(dto);
        bookingRepository.save(entity);

        // 3. 返回VO
        return convertToVO(entity);
    }
}
```

### 3.2 规范要求
1. **必须加 `@Service` 注解**
2. **必须加 `@Slf4j` 日志注解**
3. **涉及多表操作必须加 `@Transactional(rollbackFor = Exception.class)`**
4. **业务逻辑必须写在 Service，不能写在 Controller 或 Repository**
5. **返回 VO 对象，不能返回 Entity**

## 四、Repository 规范

### 4.1 基本结构
```java
@Repository
public interface BookingRepository extends JpaRepository<BookingMaster, Long> {

    List<BookingMaster> findByStoreIdAndStatus(Long storeId, String status);

    @Query("SELECT b FROM BookingMaster b WHERE b.customerPhone = :phone")
    List<BookingMaster> findByCustomerPhone(@Param("phone") String phone);
}
```

### 4.2 规范要求
1. **必须继承 `JpaRepository<Entity, ID>`**
2. **简单查询用方法命名规则**：`findByXxx`
3. **复杂查询用 `@Query` 注解**
4. **禁止在 Repository 写业务逻辑**

## 五、Entity 规范

### 5.1 基本结构
```java
@Entity
@Table(name = "booking_master")
@Data
@NoArgsConstructor
@AllArgsConstructor
public class BookingMaster {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "store_id", nullable = false)
    private Long storeId;

    @Column(name = "booking_time", nullable = false)
    private LocalDateTime bookingTime;

    @Column(name = "status", nullable = false)
    @Enumerated(EnumType.STRING)
    private BookingStatus status;

    @Column(name = "is_deleted", nullable = false)
    private Boolean isDeleted = false;

    @Column(name = "created_at", nullable = false)
    private LocalDateTime createdAt;

    @Column(name = "updated_at")
    private LocalDateTime updatedAt;
}
```

### 5.2 规范要求
1. **必须加 `@Entity` 和 `@Table` 注解**
2. **必须加 `@Data`、`@NoArgsConstructor`、`@AllArgsConstructor`**
3. **字段必须加 `@Column` 注解，标注 `nullable`**
4. **枚举字段必须加 `@Enumerated(EnumType.STRING)`**
5. **必须包含审计字段**：`createdAt`、`updatedAt`、`isDeleted`
6. **金额字段必须用 `BigDecimal`，禁止用 `Double`**

## 六、DTO/VO 规范

### 6.1 DTO（入参）
```java
@Data
public class BookingCreateDTO {

    @NotNull(message = "门店ID不能为空")
    private Long storeId;

    @NotNull(message = "预订时间不能为空")
    @Future(message = "预订时间必须是未来时间")
    private LocalDateTime bookingTime;

    @NotBlank(message = "客户姓名不能为空")
    @Size(max = 50, message = "客户姓名不能超过50字")
    private String customerName;

    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式不正确")
    private String customerPhone;
}
```

### 6.2 VO（出参）
```java
@Data
public class BookingVO {

    private Long id;
    private Long storeId;
    private String storeName;
    private LocalDateTime bookingTime;
    private String status;
    private String statusDesc;
    private String customerName;
    private String customerPhone;
    private LocalDateTime createdAt;
}
```

### 6.3 规范要求
1. **DTO 必须加校验注解**：`@NotNull`、`@NotBlank`、`@Size`、`@Pattern`
2. **VO 不能包含敏感字段**：密码、身份证号等
3. **DTO/VO 不能直接返回 Entity**，必须转换
4. **使用 MapStruct 或手动转换**，禁止 BeanUtils.copyProperties（类型不安全）

## 七、异常处理规范

### 7.1 自定义异常
```java
public class BusinessException extends RuntimeException {

    private final Integer code;

    public BusinessException(String message) {
        super(message);
        this.code = 500;
    }

    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
    }
}
```

### 7.2 全局异常处理
```java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        log.error("业务异常: {}", e.getMessage());
        return Result.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldError().getDefaultMessage();
        return Result.error(400, message);
    }

    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常", e);
        return Result.error(500, "系统繁忙，请稍后重试");
    }
}
```

## 八、日志规范

### 8.1 日志级别
| 级别 | 使用场景 |
|------|---------|
| ERROR | 系统异常、业务异常（需要人工介入） |
| WARN | 业务警告（如库存不足、参数异常） |
| INFO | 关键业务操作（如创建订单、支付成功） |
| DEBUG | 调试信息（开发环境使用） |

### 8.2 日志格式
```java
// ✅ 正确
log.info("创建预订成功, bookingId={}, customerName={}", booking.getId(), booking.getCustomerName());

// ❌ 错误
log.info("创建预订成功");  // 缺少关键信息
log.info("创建预订成功, bookingId=" + booking.getId());  // 字符串拼接，性能差
```

### 8.3 规范要求
1. **必须使用 `@Slf4j` 注解**
2. **禁止使用 `System.out.println`**
3. **日志必须包含关键业务字段**：ID、金额、状态等
4. **异常日志必须打印堆栈**：`log.error("xxx", e)`

## 十、性能规范

### 10.1 数据库查询
1. **禁止在循环中查询数据库**
2. **使用批量查询**：`findAllByIdIn(ids)`
3. **分页查询必须加索引**
4. **避免 `SELECT *`，只查询需要的字段**

### 10.2 缓存使用
1. **热点数据必须加缓存**：门店信息、字典数据
2. **缓存过期时间合理设置**：5分钟~1小时
3. **缓存穿透防护**：空值缓存、布隆过滤器

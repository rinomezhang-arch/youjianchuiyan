# 多表事务与回滚规则

> 适用：跨表写操作场景  
> 维护：地龙（DL-BOT）  
> 更新：2026-08-02

## 1. 事务基本规则

### 1.1 强制事务场景

| 场景 | 涉及表 | 事务要求 |
|------|-------|---------|
| 创建预订 | `booking_master` + `booking_table` + `table_master` | 必须，3 表原子 |
| 修改预订菜品 | `booking_dish_detail`（删+插）+ `booking_master.total_amount` | 必须 |
| 点单下单 | `orders` + `booking_dish_detail` + `booking_master` | 必须 |
| 采购入库 | `purchase_receipt` + `purchase_receipt_detail` + `ingredient_master` | 必须 |
| 库存盘点 | `stock_take` + `stock_take_detail` + `stock_loss` + `ingredient_master` | 必须 |
| 报销审批 | `reimbursement` + `finance_expense` + `finance_voucher` | 必须 |
| 调拨出库 | `stock_transfer` + `tool_inventory`（双仓） | 必须 |
| 员工离职 | `staff_master` + `employee_lifecycle` + `salary`（结算） | 必须 |
| 套餐保存 | `package_master` + `package_dish_detail`（删+插） | 必须 |

### 1.2 单表 CRUD 也加事务

约定：**所有写操作（POST/PUT/DELETE）一律 `@Transactional`**，保持一致性。

## 2. 事务传播行为

| 场景 | 传播 | 用法 |
|------|------|------|
| 默认 | `REQUIRED` | `@Transactional` 无参 |
| 嵌套审计日志 | `REQUIRES_NEW` | `@Transactional(propagation=Propagation.REQUIRES_NEW)` |
| 只读查询 | `REQUIRED` + readOnly | `@Transactional(readOnly=true)` |

**审计日志独立事务**：保证主业务回滚时审计日志仍能记录（用于追踪失败原因）：
```java
@Service
public class AuditLogService {
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void saveAuditLog(AuditLog log) {
        auditLogRepo.save(log);
    }
}
```

## 3. 异常回滚规则

### 3.1 默认行为
- `RuntimeException` / `Error` → 自动回滚
- `Checked Exception` → **不回滚**（Spring 默认）

### 3.2 强制对所有异常回滚

```java
@Transactional(rollbackFor = Exception.class)
public Result<?> doSave(...) { ... }
```

### 3.3 try-catch 中的手动回滚

**关键**：Controller 中 try-catch 会吞掉异常，导致事务不回滚。必须显式标记：

```java
@PostMapping("/customers")
@Transactional
public Result<Customer> create(@RequestBody CustomerMaster customer) {
    try {
        // 业务
        return Result.success(customerRepo.save(customer));
    } catch (DuplicateKeyException e) {
        // 唯一约束冲突 → 需要回滚
        TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        return Result.error(409, "客户已存在");
    } catch (Exception e) {
        // 兜底 → 需要回滚
        TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        return Result.error(500, "创建失败: " + e.getMessage());
    }
}
```

**陷阱**：忘记 `setRollbackOnly()` 会导致数据不一致。

## 4. 跨表事务示例

### 4.1 创建预订（3 表原子）

```java
@PostMapping("/api/bookings")
@Transactional
public Result<BookingMaster> createBooking(@RequestBody BookingMaster booking) {
    try {
        // 1. 生成订单号
        String bookingId = OrderNumberGenerator.generate("BK");
        booking.setBookingId(bookingId);
        booking.setBookingStatus("confirmed");
        booking.setCreatedAt(LocalDateTime.now());

        // 2. 插入主表
        BookingMaster saved = bookingRepo.save(booking);

        // 3. 占用桌台（多张）
        for (Integer tableId : booking.getTableIds()) {
            // 3.1 检查桌台是否空闲
            Map<String, Object> table = jdbc.queryForMap(
                "SELECT table_id, table_status FROM table_master WHERE table_id=? AND store_id=?",
                tableId, booking.getStoreId());
            if (!"idle".equals(table.get("table_status"))) {
                throw new IllegalStateException("桌台 " + tableId + " 已被占用");
            }
            // 3.2 占用桌台
            jdbc.update("UPDATE table_master SET table_status='reserved' WHERE table_id=? AND store_id=?",
                tableId, booking.getStoreId());
            // 3.3 插入预订-桌台关联
            jdbc.update("INSERT INTO booking_table (booking_id, table_id, store_id, booking_date) VALUES (?,?,?,?)",
                bookingId, tableId, booking.getStoreId(), booking.getBookingDate());
        }

        // 4. 发送通知（落库 + MQ，失败不阻断主流程）
        notifyPublisher.publish(NotifyEvent.builder()
            .eventType(NotifyEvent.NotifyType.BOOKING_CREATED)
            .storeId(booking.getStoreId())
            .title("新预订 " + bookingId)
            .relatedType("booking")
            .relatedId(saved.getId())
            .build());

        return Result.success(saved);
    } catch (Exception e) {
        TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        return Result.error(500, "创建预订失败: " + e.getMessage());
    }
}
```

**事务保证**：以上任意一步失败，整个事务回滚，桌台状态、关联记录、主表记录全部撤销。

### 4.2 套餐保存（删 + 插 + 更新）

```java
@PutMapping("/api/packages/{id}")
@Transactional
public Result<?> updatePackage(@PathVariable Long id, @RequestBody PackageDTO dto) {
    try {
        // 1. 更新主表
        packageRepo.save(toEntity(dto));

        // 2. 删除旧菜品关联
        packageDishRepo.deleteByPackageId(id);

        // 3. 重新插入所有菜品（保证数量/顺序/备注正确落盘）
        for (DishItem dish : dto.getDishes()) {
            packageDishRepo.save(toDishEntity(id, dish));
        }

        // 4. 重算套餐价格
        BigDecimal totalPrice = dto.getDishes().stream()
            .map(d -> d.getUnitPrice().multiply(new BigDecimal(d.getQuantity())))
            .reduce(BigDecimal.ZERO, BigDecimal::add);
        packageRepo.updatePrice(id, totalPrice);

        return Result.success();
    } catch (Exception e) {
        TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        return Result.error(500, "保存失败");
    }
}
```

## 5. 非事务场景的补偿

某些跨服务操作（如调用第三方短信、MQ 发送）无法纳入数据库事务，采用**对账补偿**：

1. **预写记录**：先在 `sys_notification` 表插入一条 `status=pending` 记录
2. **执行操作**：发送 MQ / 短信
3. **更新状态**：成功后 `UPDATE sys_notification SET status='published'`
4. **定时对账**：定时任务扫描 `pending` 超过 N 分钟的记录，重试或告警

## 6. 死锁与超时

### 6.1 锁顺序
跨表加锁时保持**表顺序一致**，避免死锁：
- 约定：先锁主表，后锁子表；先锁父表，后锁子表
- 示例：`booking_master` → `booking_table` → `table_master`

### 6.2 锁超时
```yaml
spring:
  datasource:
    hikari:
      connection-timeout: 30000  # 30s
      idle-timeout: 600000
      max-lifetime: 1800000
```

InnoDB 锁等待超时：
```sql
SET innodb_lock_wait_timeout = 30;  -- 30秒
```

### 6.3 死锁检测
MySQL 默认开启 `innodb_deadlock_detect=ON`，死锁时主动回滚代价小的事务。应用层捕获 `DeadlockLoserDataAccessException` 重试。

```java
@SpringBootTest
class BookingServiceTest {
    @Autowired BookingController controller;

    @Test
    @Transactional  // 测试自身事务，结束自动回滚（不影响真实数据）
    void testCreateBookingRollback() {
        // 模拟桌台已被占用，应失败回滚
        assertThrows(IllegalStateException.class, () -> {
            controller.createBooking(invalidBooking);
        });
        // 验证：booking_master 无新记录、table_master 状态未变
    }
}
```

## 8. 检查清单

| 检查项 | 是/否 |
|-------|------|
| 写操作都加了 `@Transactional` | ☐ |
| 跨表写操作在同一事务中 | ☐ |
| try-catch 内显式 `setRollbackOnly()` | ☐ |
| 嵌套审计日志用 `REQUIRES_NEW` | ☐ |
| 跨表加锁顺序一致 | ☐ |
| 唯一约束兜底 | ☐ |
| MQ/短信等非事务操作有对账补偿 | ☐ |

# 客户短信通知模板

> 版本：V2.0  | 创建日期：2026-08-02 | 维护：产品经理(天龙)

---

## 1. 文档说明

本文档定义又见炊烟餐饮管理系统 2.0 客户短信通知模板，覆盖预订、宴会、结账、会员、营销、回访等 14 个通知场景。所有模板含变量占位符，由后端 NotifyPublisher 经 RabbitMQ 异步推送至短信通道。短信开关由配置参数 `notify.sms_enabled` 控制（默认 false，待短信通道接入后开启）。模板内容须符合工信部短信签名规范，签名【又见炊烟】前置。

### 1.1 模板字段说明

| 字段 | 说明 |
|------|------|
| 场景 | 触发短信的业务场景 |
| 模板编号 | 系统内唯一标识，SMS-XXX 格式 |
| 短信内容 | 含变量占位符的模板文本，变量用 ${} 包裹 |
| 变量说明 | 各占位符含义与取值来源 |
| 发送时机 | 触发短信的具体时间点与业务事件 |

### 1.2 发送规范
- 签名：【又见炊烟】统一前置。
- 字数：单条短信 ≤ 70 字（含签名），超长自动拆分计费。
- 时段：营销类短信仅 8:00-21:00 发送；通知类短信全天可发，但 22:00-8:00 仅紧急通知。
- 退订：营销类短信末尾追加"回 T 退订"。
- 失败重试：发送失败自动重试 3 次，间隔 1/5/30 分钟，仍失败记入 sys_notification 状态 failed。

## 3. 短信发送流程

### 3.1 发送链路

```
业务事件触发
    |
    v
NotifyPublisher 构造 NotifyEvent
    |
    v
RabbitMQ 队列（notify.queue，持久化）
    |
    v
NotifyConsumer 消费
    |
    v
调用短信通道 API（待接入）
    |
    v
写入 sys_notification（status: sending -> read/failed）
```

### 3.2 失败处理
- 短信通道返回失败：自动重试 3 次，间隔 1/5/30 分钟。
- 重试仍失败：sys_notification.status 置 failed，前端站内信兜底展示。
- 退订用户：member_card.unsubscribe=1 的会员不发送营销类短信（SMS-008/009/010/014）。

### 3.3 变量渲染
- 变量统一由后端 NotifyPublisher 渲染，前端不参与。
- 渲染前校验变量非空，缺失变量用"-"占位，避免出现 ${xxx} 原文。
- 金额变量保留 2 位小数，日期变量格式 yyyy-MM-dd，时间变量格式 HH:mm。

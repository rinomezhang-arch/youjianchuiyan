## 三、关键问题发现

### 🔴 问题1：前端路径混乱
- `booking.js` 里混了：桌位(/api/tables)、预定(/api/bookings)、仪表盘(/api/dashboard)、客户(/api/customers)、菜品(/api/dishes)、食谱(/api/recipes)、套餐(/api/packages)、员工(/api/staff || /menu-api/staff)、供应商(/menu-api/suppliers)、食材(/menu-api/ingredients)、库存(/menu-api/inventory)、采购(/menu-api/purchases)、上传(/api/upload)
- **前端用了 `/api/xxx` 和 `/menu-api/xxx` 两种路径前缀，但后端统一是 `/api/xxx`！**
- `hr.js` 用 `/hr/staff` 而 `booking.js` 用 `/staff`，指向同一个Controller的不同端点

### 🔴 问题2：menu_api.js 独立菜单系统
- 存在独立的 `menu_api.js`（78KB），似乎是一套完整的菜单管理API
- 调用路径全部是 `/menu-api/xxx`
- 后端没有对应的 `/menu-api` Controller！这些请求会 **404**

### 🔴 问题3：前端API文件重复/分散
- `customer.js` 和 `booking.js` 都定义了客户相关函数
- 同样的函数在两个文件里重复定义

### 🟡 问题4：部分后端功能前端未对接
- ChangeLogController（操作日志）→ 前端无对应API
- KitchenController（后厨看板）→ 前端无对应API
- AiMemoryController（AI记忆管理）→ 前端无对应API
- ServerController（服务器管理）→ 前端无对应API
- Leave/Overtime/Schedule（请假/加班/排班）在 hr.js 只定义了查询和创建，缺审批接口

### 🟡 问题5：Booking 实体字段不完整
Booking.java 输出被截断，需确认以下字段：
- booking_status, total_amount, paid_amount, remark 等核心字段
- 对应 booking_master 表需要完整schema

## 五、致命问题汇总

### 🔴🔴🔴 致命：menu_api.js 路径完全不对
`booking.js` 里大量用了 `/menu-api/xxx` 路径，但后端根本没有 `/menu-api` 这个 Controller！

涉及：供应商、食材、库存、采购 — 全部指向了不存在的端点。

### 🔴🔴 严重：数据库不存在
当前MySQL里 **banquet库整个缺失**，没有表结构、没有数据、没有备份。

### 🟡 中等：前端API函数重复
booking.js 和 package.js、hr.js、customer.js 之间存在函数重复定义。

### 🟡 中等：缺失的CRUD端点
30+个后端端点在前端没有对应调用函数。

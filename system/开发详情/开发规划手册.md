# 后端与数据库对齐开发规划手册

> **目标**: 确保 Spring Boot JPA 实体类 (`@Entity`) 与 MySQL 数据库表结构 100% 对齐，消除启动异常、数据丢失和类型不兼容风险。
> **依据**: 基于 `项目核心记忆_餐饮管理系统.md` 和 `数据库设计使用说明书.md`。

---

## 1. 任务概述

- **当前状态**: 数据库层面已完成审计和修复（V4-V11），但 Java 实体类与数据库表的最终对齐尚未系统性验证。
- **核心风险**: 若实体类与数据库不匹配，将导致应用启动失败、运行时 SQL 异常或静默数据丢失。
- **执行策略**: 先静态扫描比对，再分批修复，最后动态测试验证。

---

## 2. 对齐检查清单 (Alignment Checklist)

| 序号 | 检查项 | 检查标准 | 优先级 |
| :--- | :--- | :--- | :--- |
| 1 | **实体类存在性** | 数据库中有表，Java 中必须有对应 `@Entity` 类。 | P0 (Fatal) |
| 2 | **字段映射** | 实体类的每个字段（含 `@Column`）必须对应数据库中的列。 | P0 (Fatal) |
| 3 | **类型兼容性** | Java 类型与 MySQL 类型必须匹配（见附录映射表）。 | P0 (Fatal) |
| 4 | **约束一致性** | `nullable`, `unique`, `length` 注解必须与数据库约束一致。 | P1 (High) |
| 5 | **主键策略** | `@Id`, `@GeneratedValue` 必须与数据库主键/自增策略一致。 | P1 (High) |
| 6 | **时间戳钩子** | 必须有 `@PrePersist` / `@PreUpdate` 处理 `created_at` / `updated_at`。 | P1 (High) |
| 7 | **级联关系** | `@OneToMany`, `@ManyToOne` 的 `cascade` 和 `fetch` 必须合理。 | P2 (Medium) |
| 8 | **索引优化** | 频繁查询字段应添加 `@Index` 或 `@Table(indexes=...)`。 | P2 (Medium) |

---

## 3. 执行步骤 (Execution Steps)

### Phase 1: 静态扫描与差异分析 (Static Analysis)
1.  **提取数据库元数据**:
    - 目标: 获取所有表的列名、类型、约束、默认值。
    - 工具: MySQL Workbench / Navicat / `SHOW CREATE TABLE` 脚本。
2.  **提取实体类元数据**:
    - 目标: 解析所有 `@Entity` 类的字段定义。
    - 方法: 读取 `banquet_project/src/main/java/.../entity/` 下所有 Java 文件。
3.  **生成差异报告**:
    - 目标: 对比两者，生成 `diff_report.md`。
    - 输出: 列出所有 P0/P1/P2 级别的不匹配项。

### Phase 2: 修复与验证 (Fix & Verify)
- **原则**: 优先修复 P0 级错误，再处理 P1/P2。
- **操作**:
    - 对于实体类缺失字段/注解：直接修改 Java 代码。
    - 对于数据库结构差异：生成 `.sql` 迁移脚本（`scripts/migrations/`）。
- **验证**: 每次修复后执行 `mvn compile` 和启动应用测试。

### Phase 3: 动态测试与回归 (Dynamic Testing)
- **接口测试**: 使用 Postman/curl 对核心 CRUD 接口进行回归测试。
- **数据写入测试**: 确保测试数据能成功写入，无截断或格式错误。
- **日志监控**: 检查 `error.log` 无异常。

## 4. 类型映射参考表 (Type Mapping Reference)

| Java 类型 | MySQL 类型 | 说明 |
| :--- | :--- | :--- |
| `String` | `VARCHAR(n)` / `TEXT` | 必须指定 `length`。 |
| `Integer` | `INT` | 非空时用 `Integer`，空值用 `Integer` (包装类)。 |
| `Long` | `BIGINT` | 主键或计数。 |
| `BigDecimal` | `DECIMAL(m,n)` | 精确小数（金额）。 |
| `Boolean` | `TINYINT(1)` | 0/1 转换。 |
| `LocalDateTime` | `DATETIME` / `TIMESTAMP` | 需要 JPA 支持。 |
| `LocalDate` | `DATE` | 仅日期。 |
| `Enum` | `VARCHAR(n)` / `INTEGER` | 推荐使用 `String` 存储状态。 |

---

## 5. 风险与注意事项 (Risks & Notes)

- **生产环境**: 所有结构变更必须通过迁移脚本执行，禁止直接修改生产库。
- **回滚策略**: 每次变更前必须备份数据库 (`mysqldump`)。
- **性能影响**: `varchar` 长度变更可能影响索引和查询计划，需谨慎。
- **权限验证**: 涉及远程服务器操作需等待用户授权。

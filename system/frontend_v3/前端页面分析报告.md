## 四、后端API接口分析

### 4.1 已定义的API模块

#### booking.js (核心业务API)
```javascript
// 桌台管理
GET    /tables                    - 获取桌台列表
POST   /tables                    - 创建桌台
PUT    /tables/:id                - 更新桌台
DELETE /tables/:id                - 删除桌台
POST   /tables/reorder            - 桌台排序
POST   /tables/swap-booking       - 换桌

// 预订管理
GET    /bookings                  - 预订列表
GET    /bookings/list             - 预订列表(分页)
POST   /bookings                  - 创建预订
PUT    /bookings/:id              - 更新预订
DELETE /bookings/:id              - 取消预订
GET    /bookings/:id              - 预订详情

// 仪表板
GET    /dashboard/today           - 今日概览
GET    /dashboard/report          - 报表数据

// 客户管理
GET    /customers                 - 客户列表
POST   /customers                 - 创建客户
PUT    /customers/:id             - 更新客户
GET    /customers/search          - 搜索客户
GET    /customers/:id/history     - 客户历史

// 菜品管理
GET    /dishes                    - 菜品列表
POST   /dishes                    - 创建菜品
PUT    /dishes/:id                - 更新菜品

// 配方管理
GET    /recipes/:dishId           - 获取配方
POST   /recipes/:dishId           - 保存配方
GET    /recipes/dishes-with-recipe - 有配方的菜品
POST   /recipes/recalc-all        - 重新计算所有配方
```

### 5.1 架构问题

1. **API模块重复**：`booking.js` 包含了客户、套餐、菜品、桌台、员工等多个领域的API，与其他专用模块重复

3. **路由守卫未实现**：`router.beforeEach` 中 `requiresAuth` 检查为空，未实现实际的登录验证

   - 最大：SupplyChain.vue (80KB, 2588行)

   - 部分页面使用 `@/api/xxx` 模块

   - 建议统一使用 API 模块

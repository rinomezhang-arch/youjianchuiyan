### 1.3 字段约定

- **多租户隔离**：所有业务表强制 `store_id` 字段（`bigint`，1=宁国店，2=宣城店）
- **字符集**：`utf8mb4` + `utf8mb4_unicode_ci`（部分老表用 `utf8mb4_0900_ai_ci`）
- **时间字段**：`created_at` / `updated_at` 默认 `CURRENT_TIMESTAMP`，`updated_at` 加 `ON UPDATE`
- **状态字段**：多用 `tinyint`（1=启用 0=禁用）或 `varchar(20)` 字典编码
- **金额字段**：`decimal(12,2)`，比例字段 `decimal(10,2)`

### 1.4 约束与索引

- 主键：均使用 `AUTO_INCREMENT` 整型
- 唯一键：业务编码（如 `uk_booking_id` / `uk_role_code` / `uk_dict_code`）
- 外键：仅在关键关联表使用（如 `fk_bm_customer` → `customer_master`，`fk_bm_staff` → `staff_master`）
- 复合索引：覆盖 `store_id` + 业务字段（如 `idx_store_phone`、`uk_role_perm`）

### 2.2 事务边界

- 写操作（POST/PUT/DELETE）一律 `@Transactional`
- 跨表操作（如预订+桌台、点单+库存）失败时通过 `TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()` 回滚
- 异常统一 try-catch 返回 `Result.error(500, ...)`，避免堆栈泄漏

### 2.3 权限拦截点

- **认证**：`AuthInterceptor` 拦截 `requiresAuth` 路由，校验 JWT token
- **门店隔离**：`StoreDataScopeAspect` 在 GET 请求前置填充 `UserContext`，店长强制 `storeId=本店`
- **越权防护**：写操作调用 `UserContext.assertStoreAccess(targetStoreId)`，非 GM 越权写返回 `403`
- **接口权限**：`sys_permission` 表定义 20 个权限点（见第 6 节）

router.beforeEach(async (to, from, next) => {
  if (to.meta.requiresAuth) {
    const token = localStorage.getItem('token')
    if (!token) return next({ path: '/login', query: { redirect: to.fullPath } })
    // token 校验 + 用户信息初始化
    if (!userStore.initialized) await userStore.init()
    if (!userStore.isLoggedIn) return next({ path: '/login', query: { redirect: to.fullPath } })
    next()
  } else next()
})

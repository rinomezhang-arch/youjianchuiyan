## 三、具体SQL脚本（按顺序执行）

### Step 1：删除重复表（保留一套，迁移数据后删除）

**原则**：保留名称更规范、数据更全的表；若数据量相当，保留有外键关联的表。

```sql
-- 1. 采购申请：保留 purchase_request，删除 procurement_request、purchase_order（如数据需迁移，先INSERT IGNORE）
--    若 procurement_request 有数据，请先手动迁移，此处假设无数据或已废弃。
DROP TABLE IF EXISTS procurement_request;
DROP TABLE IF EXISTS procurement_request_item;
DROP TABLE IF EXISTS purchase_order;
DROP TABLE IF EXISTS purchase_order_detail;

-- 2. 验收入库：保留 goods_receipt，删除 purchase_receipt
DROP TABLE IF EXISTS purchase_receipt;
DROP TABLE IF EXISTS purchase_receipt_detail;

-- 3. 领料：保留 material_requisition，删除 requisition_order
DROP TABLE IF EXISTS requisition_order;
DROP TABLE IF EXISTS requisition_detail;

-- 4. 成本卡：保留 cost_card（新版），删除 dish_cost_card（旧版）。若旧版有数据需迁移，请先处理。
--    注：两个表结构略有不同，若需保留数据，请先转换再删除，此处假设旧版无数据或已废弃。
DROP TABLE IF EXISTS dish_cost_card;
DROP TABLE IF EXISTS dish_cost_card_detail;

-- 5. 套餐菜品关系：保留 package_dish_detail，删除 package_dish_rel
--    若有数据需迁移，请先 INSERT INTO package_dish_detail SELECT ... 再删除。
DROP TABLE IF EXISTS package_dish_rel;
```

> ⚠️ **注意**：删除前务必确认无数据依赖。若仍有数据需要保留，请先迁移后再执行DROP。

### Step 2：统一字段类型（解决类型不一致）

```sql
-- 2.1 package_dish_rel 已删除，无需修改。但 package_dish_detail 中 package_id 是 varchar(20)，与父表一致，没问题。

-- 2.3 修改 goods_receipt.supplier_id（bigint → int）
ALTER TABLE goods_receipt MODIFY supplier_id INT COMMENT '供应商ID';

-- 2.4 修改 finance_receivable.booking_id（int → bigint）

-- 2.5 检查 dish_master.dish_id 已为 varchar(20)，无需修改。
```

### Step 3：添加缺失的外键约束（确保数据完整性）

按依赖顺序（主表 → 子表）添加：

```sql
-- 3.1 cost_card → dish_master
ALTER TABLE cost_card ADD CONSTRAINT fk_cost_card_dish 
    FOREIGN KEY (dish_id, store_id) REFERENCES dish_master(dish_id, store_id);

-- 3.2 cost_card_detail → cost_card
ALTER TABLE cost_card_detail ADD CONSTRAINT fk_cost_card_detail_card 
    FOREIGN KEY (cost_card_id) REFERENCES cost_card(cost_card_id);

-- 3.3 cost_card_detail → ingredient_master
ALTER TABLE cost_card_detail ADD CONSTRAINT fk_cost_card_detail_ingredient 
    FOREIGN KEY (ingredient_id, store_id) REFERENCES ingredient_master(ingredient_id, store_id);

-- 3.4 purchase_request_item → purchase_request
ALTER TABLE purchase_request_item ADD CONSTRAINT fk_purchase_request_item_req 
    FOREIGN KEY (request_id) REFERENCES purchase_request(request_id);

-- 3.5 goods_receipt → purchase_request（request_id 可为空，但若存在则需约束）
ALTER TABLE goods_receipt ADD CONSTRAINT fk_goods_receipt_request 
    FOREIGN KEY (request_id) REFERENCES purchase_request(request_id);

-- 3.6 goods_receipt → supplier_master
ALTER TABLE goods_receipt ADD CONSTRAINT fk_goods_receipt_supplier 
    FOREIGN KEY (supplier_id) REFERENCES supplier_master(supplier_id);

-- 3.7 goods_receipt_item → goods_receipt
ALTER TABLE goods_receipt_item ADD CONSTRAINT fk_goods_receipt_item_receipt 
    FOREIGN KEY (receipt_id) REFERENCES goods_receipt(receipt_id);

-- 3.8 material_requisition_item → material_requisition
ALTER TABLE material_requisition_item ADD CONSTRAINT fk_requisition_item_req 
    FOREIGN KEY (requisition_id) REFERENCES material_requisition(requisition_id);

-- 3.9 preprocessing_record → ingredient_master
ALTER TABLE preprocessing_record ADD CONSTRAINT fk_preprocessing_ingredient 
    FOREIGN KEY (ingredient_id, store_id) REFERENCES ingredient_master(ingredient_id, store_id);

-- 3.10 finance_transaction → finance_account
ALTER TABLE finance_transaction ADD CONSTRAINT fk_finance_trans_account 
    FOREIGN KEY (account_id) REFERENCES finance_account(account_id);

-- 3.11 finance_expense → staff_master（applicant_id）
ALTER TABLE finance_expense ADD CONSTRAINT fk_expense_applicant 
    FOREIGN KEY (applicant_id) REFERENCES staff_master(staff_id);

-- 3.12 finance_expense → finance_account（account_id）
ALTER TABLE finance_expense ADD CONSTRAINT fk_expense_account 
    FOREIGN KEY (account_id) REFERENCES finance_account(account_id);

-- 3.13 finance_receivable → customer_master
ALTER TABLE finance_receivable ADD CONSTRAINT fk_receivable_customer 
    FOREIGN KEY (customer_id) REFERENCES customer_master(customer_id);

-- 3.14 finance_receivable → booking_master（已改类型）
ALTER TABLE finance_receivable ADD CONSTRAINT fk_receivable_booking 
    FOREIGN KEY (booking_id) REFERENCES booking_master(id);

-- 3.15 finance_payable → supplier_master
ALTER TABLE finance_payable ADD CONSTRAINT fk_payable_supplier 
    FOREIGN KEY (supplier_id) REFERENCES supplier_master(supplier_id);

-- 3.16 package_dish_detail → package_master
ALTER TABLE package_dish_detail ADD CONSTRAINT fk_package_detail_package 
    FOREIGN KEY (package_id, store_id) REFERENCES package_master(package_id, store_id);

-- 3.17 package_dish_detail → dish_master
ALTER TABLE package_dish_detail ADD CONSTRAINT fk_package_detail_dish 
    FOREIGN KEY (dish_id, store_id) REFERENCES dish_master(dish_id, store_id);

-- 3.18 booking_table → booking_master
ALTER TABLE booking_table ADD CONSTRAINT fk_booking_table_booking 
    FOREIGN KEY (booking_master_id) REFERENCES booking_master(id);

-- 3.19 booking_table → table_master
ALTER TABLE booking_table ADD CONSTRAINT fk_booking_table_table 
    FOREIGN KEY (table_id) REFERENCES table_master(table_id);

-- 3.20 staff_master → department
ALTER TABLE staff_master ADD CONSTRAINT fk_staff_dept 
    FOREIGN KEY (dept_id) REFERENCES department(dept_id);

-- 3.21 ingredient_purchase → ingredient_master（已存在，但若缺失则补充）
--    如果之前已有外键，可跳过，否则添加：
-- ALTER TABLE ingredient_purchase ADD CONSTRAINT fk_ingredient_purchase_ing 
--     FOREIGN KEY (ingredient_id, store_id) REFERENCES ingredient_master(ingredient_id, store_id);

-- 3.22 ingredient_inventory_log → ingredient_master
ALTER TABLE ingredient_inventory_log ADD CONSTRAINT fk_inventory_log_ingredient 
    FOREIGN KEY (ingredient_id, store_id) REFERENCES ingredient_master(ingredient_id, store_id);
```

### Step 5：新增库存汇总表（用于P4库存汇总API）

```sql
CREATE TABLE IF NOT EXISTS inventory_summary (
    summary_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    store_id BIGINT NOT NULL COMMENT '门店ID',
    ingredient_id VARCHAR(50) NOT NULL COMMENT '食材ID',
    total_quantity DECIMAL(12,3) NOT NULL DEFAULT 0 COMMENT '当前总库存数量',
    total_cost DECIMAL(12,2) NOT NULL DEFAULT 0 COMMENT '当前库存总成本（按加权平均）',
    avg_unit_price DECIMAL(10,4) NOT NULL DEFAULT 0 COMMENT '加权平均单价',
    update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_store_ingredient (store_id, ingredient_id),
    FOREIGN KEY (ingredient_id, store_id) REFERENCES ingredient_master(ingredient_id, store_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='库存汇总表（冗余加速查询）';
```

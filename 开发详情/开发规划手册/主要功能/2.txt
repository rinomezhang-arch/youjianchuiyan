# 餐饮宴会系统全链路整改操作报告（数据库+后端+前端一体化）

---

## 一、整改背景与目标

### 1.1 现状问题

- **数据库**：存在5组重复业务表、父子表字段类型不匹配、大量冗余字段、缺少物理外键、无库存汇总表，导致数据不一致和报表查询缓慢。
- **后端（Spring Boot + JPA）**：实体映射字段与库表不一致（采购数量/金额为空）、缺少库存汇总接口、考勤接口空指针报500。
- **前端（Vue3）**：入库验收（Receipt）、领料出库（Issue）页面为空壳，部分路由废弃，考勤打印报错，API封装不全。
- **业务断层**：采购→入库→领料→加工→成本→财务无法闭环，看板无数据支撑。

### 1.2 整改目标

- 完成数据库标准化（去重、类型对齐、建外键、清冗余、加汇总表），并导入基础测试数据。
- 同步修复后端实体映射和接口，使采购、库存、考勤等核心API可用。
- 补齐前端两个关键页面（Receipt、Issue），修复报错页面，完善API调用。
- 最终打通采购→入库→领料→初加工→成本卡的完整业务流程，确保看板正常展示。

---

### 4.3 新增库存汇总API

**1. 创建实体 `InventorySummary.java`**（略，按表生成）

**2. 创建 Repository**：
```java
@Repository
public interface InventorySummaryRepository extends JpaRepository<InventorySummary, Long> {
    List<InventorySummary> findByStoreId(Long storeId);
    Optional<InventorySummary> findByStoreIdAndIngredientId(Long storeId, String ingredientId);

```

**3. Service 实现**：
```java
@Service
public class InventoryService {
    @Autowired
    private InventorySummaryRepository summaryRepository;

    public List<InventorySummaryDTO> getInventorySummary(Long storeId) {
        return summaryRepository.findByStoreId(storeId)
                .stream()
                .map(this::convertToDTO)
                .collect(Collectors.toList());
    }

    private InventorySummaryDTO convertToDTO(InventorySummary entity) {
        InventorySummaryDTO dto = new InventorySummaryDTO();
        dto.setIngredientId(entity.getIngredientId());
        dto.setIngredientName(entity.getIngredientName()); // 若实体中无，需联表查询
        dto.setTotalQuantity(entity.getTotalQuantity());
        dto.setTotalCost(entity.getTotalCost());
        dto.setAvgUnitPrice(entity.getAvgUnitPrice());
        return dto;
    }
}
```

**4. Controller 接口**：
```java
@GetMapping("/summary")
public ResponseEntity<ApiResponse> getSummary(@RequestParam Long storeId) {
    return ResponseEntity.ok(ApiResponse.success(inventoryService.getInventorySummary(storeId)));
}
```

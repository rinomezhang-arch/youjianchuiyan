- `frontend_v3/src/views/Dashboard.vue`：删掉顶栏来回扫的金色 shimmer 动画与

  由 `global.css` 的 `@import` 引入（必须在所有规则之前）。
- 三处是**实际打开浏览器才发现的**，读代码发现不了：
  顶栏「团队聊天」按钮**从来没写过样式**，浏览器按默认控件渲染成 `border: 2px outset` 的 3D 灰块；

  提交 `23ccc4fc`。其中 select 的箭头要用 `.dashboard select[class]`（0,2,1）才压得过
  scoped 编译出的 `.xxx[data-v-hash]`（0,2,0），否则会被页面自己的 `background` 简写整个冲掉。
- **57 处两段式渐变压成实色**（"一个颜色 + 它自己调亮一点"是塑料感的主要来源）。
  只动恰好两个色标且不含 `transparent` 的；含透明的高光带、三个及以上色标的一律没动。
  提交 `6d9b1f30`。
- 八个常用页的圆角（≥4px）收到 2px、静止态大投影换成设计令牌的浅 lift。

## 我自己做错并已更正的（写全，别让下一位重蹈）

1. **把静态推断写成实测结论**。CL61 首版写了「可反复跑安全」「每次都重建表」
   「不存在数据丢失风险」——这些都没有实际执行过 DDL。统筹指出后全部降级为静态分析口径。
   **口径固定下来**：结构层面的陈述（谁引用谁、有无守卫、列名类型）读原文可核对；
   运行时行为（锁多久、会不会重建、重跑结果）一律待验证，不作数。
2. **把一条外键问题判成「阻断级」，结论是错的**。我判 `ipad_device_binding` 的
   `REFERENCES staff_master(id)` / `store_info(id)` 会阻断发布。
   TL64 到手后发现该表**生产上早就存在**，脚本是 `CREATE TABLE IF NOT EXISTS`，
   建表语句连同外键**根本不会执行**；而且生产 `staff_id` 本来就是 `int` 不是我推演的 bigint。
   **推演的前提就是错的**，已在补正件里明确撤回。
   仍成立的部分只有「脚本文本确实把被引用列名写错了」。
3. **给出去的查重 SQL 列名写错**：写成 `(id, store_id)`，实际是
   `(payable_id, store_id)` / `(receivable_id, store_id)`。已按脚本原文改正。
4. **原始 stdout 没落盘**：CL50 的 driver 输出我管道给了 `tail -70` 直接看，
   没另存重定向日志，开头约 10 行永久缺失。已写 `run-output-captured.md` 如实标出缺口，
   **没有凭记忆补写**。重跑补不回来（A 段断言要求起点为 0，库已是终态）。
5. **明文解锁码被我复制出了新副本**：生成的 prod-vs-candidate diff 里带出 1 处，
   已改 `[REDACTED-6DIGIT]`；我为归档复制的 `src-prod` 是又一份明文，
   已移入 `artifacts/trash/cl45-prod-copy-20260909`（**进垃圾桶，未删除**）且不入库。

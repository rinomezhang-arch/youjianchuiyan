```json
{"version":2,"scope":"8001:1","payload":{"requestId":"synthetic-v2-1","storeId":1,"payableNo":"PYsyntheticv21","supplierName":"SYN supplier","totalAmount":"5.00","remark":"SYN input"}}
```

POST /finance/payables发送完整payload，包括稳定requestId（生成值为UUID，校验非空且不超过64）。写前先setItem并readback确认，失败不POST。恢复只读取已保存payload，无draft入参，不生成新请求号。v2会核对内嵌scope和payload字段白名单，不能将别的账号/店记录复制过来重发。

成功期望code=200及data.requestId/payableId/payableNo/storeId/totalAmount/replayed全部匹配：ID正安全整数，storeId数字完全匹配，金额按金额规范化相等，replayed必须布尔。首次尚无旧ID可比时验证ID有效性；完整回执入journal，随后重放ID也必须一致。成功回执仍待列表唯一匹配确认后解除新增锁定。列表核对保留单号/店/供应商/金额/有效ID，已保存回执还需同ID。

首次新请求仅HTTP400/403且body.code一致才清除journal允许修正。超时、409、500、畸形回执及其他不确定错误保留。恢复请求不管HTTP400/403/409均保留，不当作首次拒绝。旧v1无requestId，不升级不重发，只做原有列表核对。损坏记录保留、锁写但可查询。

## 未覆盖与限制

这是Node前端契约、真实Vue脚本装配及SFC编译验证，业务接口为合成mock，不是JWT/HTTP/MySQL端到端，不是浏览器点击实测。未Maven、未生产部署、未动法务。

同JS运行域且共享同storage对象时有并发门控；跨标签页/进程不能靠WeakMap锁住，真正同键幂等依赖后端。sessionStorage不能防人工篡改，也不能在关闭标签页后保证恢复。列表核对没有独立查询requestId，因此延续现有名单核对规则，并对已获回执额外绑定ID；没有宣称列表匹配可替代服务端幂等证明。

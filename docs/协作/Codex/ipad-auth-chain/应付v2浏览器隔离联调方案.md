## 浏览器操作与断言

1. 正常创建：真实登录普通门店账号→进入应付页面→填写合成供应商/金额/备注→保存→看到同一单号和金额。网络请求requestId稳定且完整，回执六关键字段吻合；数据库只有一张同店应付，paid=0、pending=total；列表核对后journal清除。
2. 结果未知：隔离代理只丢弃第一次真实创建的响应（后端仍提交），不mock业务。刷新页面后应出现恢复按钮与固定原金额。点击恢复，捕获同requestId同payload；真实后端replayed=true、同payableId，数据库条数和金额不增加。故障代理仅绑定本地隔离端口，不改全局request。
3. 409：制造同键冲突/在途请求，页面保留原journal与编辑锁；随后同参数恢复。不能把名单暂未出现当未创建。
4. 身份/门店：GM未选店不能POST，明确选店后可创建；普通员工跨店403不落库；恢复后的403仍保留journal。切账号/门店不串日志；旧响应不覆盖新scope。
5. 旧v1：仅在合成浏览器sessionStorage写有标识v1记录，确认没有恢复POST按钮/调用，列表唯一匹配后解除；缺失或不匹配继续锁定。
6. 本地存储失败：仅隔离浏览器环境模拟setItem失败，证明POST次数0。畸形回执通过隔离响应变形验证客户端锁定，但另标注此例用了传输故障注入，不能当真实后端返回正常合同。
7. 跨日期：不改系统时钟/生产日期。先读Claude最终实现及测试时钟入口；如未提供可隔离控制时钟，浏览器同日链与后端可控时钟跨日真实DB合同分别报告，跨午夜浏览器端到端标未执行，不能伪称覆盖。

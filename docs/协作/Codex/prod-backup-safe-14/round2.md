# PROD-BACKUP-SAFE-14 第二轮修复登记

## 意图

根据独立审查意见收紧备份复制、恢复目标和输入文件边界。仅修改本任务独立工作树中的三个脚本及本目录记录，不连接生产、不安装任务、不改服务、配置或数据库。

## 计划验证

- 端口按十进制归一化并拒绝 3306 的前导零变体。
- 恢复库名强制使用固定 `restore_verify_` 前缀。
- 建库前拒绝 `USE`、创建或删除数据库以及跨库限定名。
- COS 副本先写同目录临时名，哈希通过后原子改名；失败或中断残片移入时间戳垃圾桶。
- 转储结束标记必须是解压后最后一个非空标准标记。
- 规范化并约束本地、COS 和恢复文件路径，拒绝父目录穿越及符号链接逃逸。
- 使用临时目录、假命令和合成 SQL 覆盖审查指定的反例，不连接真实数据库。

## 执行结果

- `prod_daily_backup.sh`：本地与 COS 目标先做绝对路径、父目录片段和 realpath 范围检查；COS 复制改为同目录隐藏临时文件，复制失败、信号退出或哈希不一致时移入 `copy-incomplete` 垃圾桶，成功后才同目录原子改名。
- `verify_backup_restore.sh`：端口按十进制归一化并限制 1 至 65535，拒绝 3306 及前导零变体；恢复前缀固定为 `restore_verify_`；备份文件限定在规范化根目录内，拒绝父目录片段与链接逃逸；建库前拒绝选库、创建或删除数据库及跨库限定 SQL。
- 两个脚本都要求解压后最后一个非空行严格匹配 mysqldump 标准日期时间结束标记。
- `test_prod_backup_safe.sh` 新增现有库、03306、前缀覆盖、跨库 SQL、复制半文件、路径穿越、目录链接逃逸及结束标记后仍有数据等反例。

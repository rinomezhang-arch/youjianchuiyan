## 发布闸门

1. 形成当前精确SHA的单一manifest，每条需求写已执行证据或未覆盖，不把历史版本成功算作当前候选成功。
2. 真实登录与批复身份必须核实；张律师原权限与法务内容冻结，不向其数据写测试记录。
3. 只读获取当前生产源码/JAR基线，逐文件忽略CRLF差异比对，保留线上较新代码。不得仅凭本地构建覆盖生产。
4. 明确迁移预检、备份恢复和回退入口；受保护内容用hash证明保留。
5. Codex核定缺口关闭后才给实际部署指令，Trae执行发布并回报部署hash、健康和真实业务回读。此前所有“候选成功”不等于生产交付。

禁止重复消耗：不复跑TR58整套浏览器和API链，不复跑CO60的15项测试；只有独立复核发现新问题或候选变化影响既有证明时才追加定向验证。阻断立即上板，由统筹裁决，不空转排查模型或账户余额。

## 当前链路

浏览器SN/门店/员工本地状态→四个请求头→active设备绑定查询→request属性→控制器与现有身份切面。PC JWT不参与/api/ipad路径。GuestOrder的账号密码校验返回普通身份字段，批量请求只回传staff_id，没有短期令牌、服务端授权ID、nonce或消费检查；“staff_id”不能当token。

## 后续建议（尚未实施）

1. 未绑定员工设备仅允许受限登录/引导入口；实际业务必须有服务端认证会话，绑定门店/设备/员工，并校验员工存在、同店、在职。不能把SN直接升级为秘密。
2. 由真实密码核验成功后签发短期、可撤销的授权凭据，或生成服务端授权记录；批量消费必须绑定门店、订单、操作目的和员工，校验期限并防重放，不能使用客户端staff_id当授权。
3. 正常共享设备换班、注销及员工离职需定义会话切换/撤销规则。可以保持门店隔离，但不能在未知业务口径下把设备永久绑死一个员工。
4. 后续合成测试需挂真实WebMvcConfig/IpadInterceptor及控制器：空绑定+伪造员工、已绑定但员工不在职、直接批量跳过verify、过期/错订单/重放授权、合法员工换班、他店订单拒绝、注销撤销。现有IpadOrderScopeTest不等于授权链测试。

本轮没有修改任何上述业务/权限/配置，未涉及法务。另见登录页fallbackOrThrow调用；未核查其运行模式，本报告不把它误报为生产假登录。

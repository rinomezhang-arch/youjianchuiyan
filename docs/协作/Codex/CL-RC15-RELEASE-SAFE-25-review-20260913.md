结论：`changes_requested`。候选已证明部分恢复控制流，但仍不能作为生产发布与回退门禁。

## 已核证

- 候选基于任务基线，工作树干净，未修改法务源码。
- 隔离证据证明前端漂移能在首笔恢复前拒绝，成功夹具可恢复前后端内容哈希。

## 必须修正

1. 发布前以任务声明的精确 SHA 和逐文件清单比对现场，禁止用 `grep` 特征或类名存在代替基线漂移门禁。
2. 法务保护、改密与登录检查逐项显式失败退出；禁止 `grep && echo` 的失败被后续成功掩盖。现有证据出现“错误密码统一文案缺失”仍宣告完成，必须修复。
3. 同一时间戳目录、manifest、备份或垃圾桶目标已存在时立即拒绝；写入前后逐文件回读备份哈希，禁止覆盖既有现场。
4. `chown` 只作用于本次白名单文件，不递归修改整个 `dist/assets`。
5. 默认回退命令必须同时恢复前端和后端，不能依赖额外环境变量才完整回退。
6. 在同一 HEAD 上补齐构建失败、备份失败、健康超时、发布前基线漂移四类故障注入，并绑定所有恢复实现和白名单文件哈希。
7. 将 `scripts/release/.gitattributes` 纳入明确范围或拆出；不得用范围外文件暗中改变运行语义。

只做发布安全脚本与隔离故障注入，不连接生产，不碰法务业务内容。

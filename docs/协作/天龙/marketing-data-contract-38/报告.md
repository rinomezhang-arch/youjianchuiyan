### R2-1 受控更新拒绝（替换 1242）— BLOCKED（不可行，回报两选项）
- 现状 1242 做法确有问题（非受控业务拒绝、文案不说明违规字段、把执行器行为当契约）。
- 建议机制"函数体单语句 SIGNAL"经实测不可行：MySQL 8.0.46 报 **1320 No RETURN found in FUNCTION**（函数必须有 RETURN，不能裸 SIGNAL）；且 PREPARE 无法建函数（**1295**）。
- 根因：MySQL 单语句触发器体内无法做"条件 SIGNAL 自定义文案"——SIGNAL 是语句非表达式，条件 SIGNAL 必须 BEGIN...END 复合体；"无 BEGIN...END/内部分号"与"文案明确(自定义 MESSAGE_TEXT)"两者互斥。
- 两个可执行选项（均实测验证）：
  - **选项A（推荐，受控文案明确）**：复合体 BEFORE UPDATE 触发器 + 条件 SIGNAL 自定义文案。ScriptUtils 用自定义分隔符 `//` 可执行（已实测 SCRIPT_OK），负例 title 更新被拒 1644 "marketing_publication 快照字段不可修改"，正例 status 更新通过。代价：迁移需改用 `//` 分隔或把触发器拆为独立脚本（非默认 `;`）。
  - **选项B（保持单语句，文案为哨兵表名）**：单语句体触发器 + CASE 短路调用函数 `RETURN (SELECT 1 FROM __refuse_...__)`，报 1146 但带迁移定义的哨兵表名。ScriptUtils 默认 `;` 可执行；但仍是 MySQL 原生错误、非受控 SIGNAL，且函数需声明 READS SQL DATA（**1418** 限制）。
- 未退回 1242；原始报错证据保留（1320/1295）。

## 要做的

新增公开最小状态查询，**同时要求 `phone` + `bookingId`**，两者缺一不可。

### 防枚举是这次的核心

- **绝不允许仅凭手机号查询**。只给手机号就能列出某人所有预订，等于送出一个客户信息接口。
- **查无 / 手机号不符 / 跨店，一律返回同一种空结果**。
  分开提示等于把接口变成校验器：拿一个 bookingId 试不同手机号，从错误差异就能反推机主。
- 用 **POST + 请求体**，不用 GET 查询串：手机号是个人信息，不该出现在 URL、日志和浏览器历史里。

### 字段白名单

只返回客人自己核对行程需要的：`bookingId`、`bookingDate`、`bookingTime`、`guestCount`、
`bookingStatus`、`tableCount`。
**不返回**客人电话（他自己已经知道，回显只会在日志里多留一份）、备注、金额、内部单号、操作人。
和之前几轮一样，白名单**在 SQL 里就定死**，不是查出来再过滤。

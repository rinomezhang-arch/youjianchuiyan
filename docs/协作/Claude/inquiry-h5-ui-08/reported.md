## 交付

### 一、公开 H5 查预订（`StoreDetail.vue`）

门店详情页新增「查询我的预订」，**手机号 + 预订单号同时填对才查得到**。

**前端与后端严格同口径**：后端把「查无 / 手机号不符 / 别人的单 / 别店的单 / 缺参数 / 格式非法」
统一成同一种空结果，前端也**只给同一句提示**，不做任何区分。
界面若按不同情况分开提示，后端刚堵住的枚举口子就在前端重新打开了——这是这块最要紧的一条。

只展示后端白名单的六个字段。金额、备注、客人自己的电话都不显示。

### 二、员工端咨询转单（`Bookings.vue`）

预订管理页新增「公开咨询待转单」面板，位置在工具栏之前：
客人已提交、还没落成正式预订的，比已有预订更急着处理。

- 日期、到店时间、桌台**三者必填**，**界面不做任何自动选桌**，与后端同口径。
- 客人的期望日期时间**预填但仍需员工确认**，不当成已定。
- 成功显示正式预订单号；**重复确认如实显示"此前已转过、未重复建单"**，
  不伪装成一次新成功——伪装会让员工以为刚建了单，转头又去建第二张。
- 转换成功后该咨询从待办列表消失，避免诱使重复点击。

### 三、契约模块（`api/publicBooking.js` + `api/publicBookingContract.js`）

纯契约逻辑单独成 `publicBookingContract.js`，**没有任何 import**，可被 node 直接单测。
这不是洁癖：统一空结果、字段白名单、三者必填、`replayed` 如实显示这几条是本轮要害，
一旦只能跟着 Vue 跑，验证成本就会高到没人验。

## 中途失败与修正（如实记录，都是我的问题不是代码缺陷）

1. **`form_input` 不触发 `input` 事件**，v-model 没同步，第一次点击什么都没发生。
   改为显式派发 `input` 事件。
2. **连续点击太快产生竞态**：Vue 重渲染把我直接赋的 `.value` 冲掉，
   第二次实际发出的还是上一组参数。改为每次等真实请求落地后再读，并逐次核对发出的 payload。
3. **只接管 XHR 不够**：axios 1.x 走 fetch 适配器，请求穿透到 vite 代理去打真后端了
   （日志里是 `ECONNREFUSED`）。两条都接管后才真正隔离。
4. 读结果 DOM 比 Vue 重渲染早一步，读到上一步的残影，导致断言错位。改为等文案确实变化再读。
5. 被测页面的 `BookingDialog` 子组件在验收台里 setup 抛错（缺会话上下文），把整页拖白。
   加 `app.config.errorHandler` 隔离子组件异常，**错误照常打到 console，不静默**。
6. `validateConvertInput` 原本只去重不排序。**改的是实现不是测试**——
   排序让 payload 确定，且与后端按 `table_id` 升序加锁同序。

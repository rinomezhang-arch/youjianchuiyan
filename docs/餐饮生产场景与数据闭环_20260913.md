# 又见炊烟餐饮生产场景与数据闭环

本文件定义系统进入生产前必须跑通的真实工作方式。它用于指导任务拆分、数据库收口、页面设计和端到端验收。法务模块及张律师既有权限不在本文件改动范围内，继续冻结。

## 一、生产角色和每天要完成的事

| 角色 | 工作入口 | 必须完成 |
|---|---|---|
| 张晓秋、张婧 | 经营驾驶舱、审批中心 | 看今日营业、待审批、资金余额、库存异常、工资和报表；批复采购、报销、盘亏、工资与付款 |
| 店长、前台 | 今日工作台、预订与桌台 | 接电话或到店快速建预订、占台、改台、收订金、到店开台、取消和查询 |
| 服务员、iPad | 桌台与点菜 | 开台、点菜、加退菜、催菜、送厨、结账；离线重试不能重复下单或收款 |
| 厨房、库管、采购 | 厨房屏、采购入库、领料、盘点 | 接单出品、收货验货、库存落账、领料加工、盘点落盘、异常报损 |
| 财务、人事 | 应收应付、收付款、工资、报表 | 来源单可追溯、审批后付款、工资审批发放、日结月结、打印与导出 |
| 客人 | H5 | 看门店、菜单、套餐和活动；提交咨询或预订；查询自己的预订，不看到内部经营数据 |

## 二、六条必须闭环的真实业务链

### 1. 客人到收款

客户或前台建预订，系统锁定门店、日期、餐段和桌台；订金形成收款来源。到店开台后点菜进入厨房，出品和退菜更新有效金额。结账必须生成账单、支付、资金流水和小票，刷新后仍可回读。

权威链：

customer_master -> booking_master -> booking_table -> booking_dish_detail -> kitchen_log -> finance_settlement/finance_receivable -> finance_payment_record -> finance_transaction -> 小票与营业报表

守恒点：

- 有效菜品小计之和等于账单应收；订金、优惠、退款和实收分别列示。
- 支付合计不得超过应收；已结清时支付合计等于最终金额。
- 每个桌台占用只在有效预订期间成立；取消保留历史后必须允许同餐段重新预订。
- 所有主单、明细、桌台、支付和流水必须同门店，不允许跨店关联。

### 2. 采购到应付

厨房或库管提出需求，张晓秋或张婧审批采购，采购到货后按供应商和批次验收入库。一次收货在同一事务内生成入库明细、库存流水、库存余额和应付；付款后生成付款记录、资金流水和凭证。

权威链：

purchase_request/purchase_order -> goods_receipt/goods_receipt_item -> ingredient_inventory_log/inventory_summary -> finance_payable -> finance_payment_record或付款明细 -> finance_transaction -> finance_voucher

守恒点：

- 收货数量乘验收单价等于收货金额；应付总额等于有效收货明细金额。
- 库存增加量等于收货实收量；库存流水的前余额加变化量等于后余额。
- 应付必须保存来源收货主键和单号，不能只靠供应商名称或备注。
- 同一收货 request_id 只能落账一次，重试返回原业务结果。

### 3. 领料、加工和菜品成本

厨房申请领料，审批时扣库存并记录当时有效入库价；加工记录毛料、净料和出成率；配方按统一单位换算得到菜品标准成本。真实的“一克多少钱”来源只读保护，模拟库存不得反写该来源。

守恒点：

- 申请不扣库存，确认领出才扣；重复确认不重复扣。
- 毛料数量、净料数量、损耗和出成率相互可算且精度一致。
- 菜品成本能逐级追到配方原料、单位换算和有效入库价。

### 4. 盘点到库存和财务

盘点页面生成当日快照，库管逐行快捷录入实际数量并保存草稿。提交后明细不可悄悄丢失；差异经厨师长、店长和财务按规则审批，最终只生成一次库存调整和盘盈盘亏财务记录。

权威链：

stock_take -> stock_take_detail -> stock_loss/stock_loss_detail -> approval_flow/approval_log -> ingredient_inventory_log/inventory_summary -> finance_transaction/finance_voucher

守恒点：

- completed 盘点必须至少有一条有效明细，total_items 等于明细数。
- 原料 ID 全链同类型；数量统一三位小数，单价八位小数，金额逐行四舍五入到分后汇总。
- 差异等于实际数量减系统数量；盘亏调整量和财务金额必须与批准明细一致。
- 任务失败或刷新不能产生空完成主单、孤儿明细或重复库存流水。

### 5. 排班考勤到工资发放

排班发布后形成应出勤基准，考勤、加班、请假、奖惩进入月度核算。工资保存后进入审批，只有张晓秋和张婧可以批复。批准后发放一次并生成工资发放台账、资金流水和凭证；员工只看本人。

权威链：

schedule/attendance/leave/overtime/reward_punish -> month_salary -> approval_flow/approval_log -> payroll_payout_record -> finance_transaction -> finance_voucher

守恒点：

- 同一员工、门店、月份只有一张有效工资单和一次有效发放。
- 实发等于应发减各项扣款；审批版本必须与发放版本一致。
- 发放记录、资金流水和工资单金额相等，状态按 pending -> approved -> paid 单向流转。
- PayrollController 与 SalaryController 必须收口到一个权威业务入口，避免同月重复核算。

### 6. 活动到客人转化

经营者创建活动或广告，选择门店、有效期、公开渠道、素材和落地页，经审批后发布到 H5。客人从活动进入咨询或预订时保存来源码，最终能统计浏览、咨询、预订、到店和收入。

权威链：

marketing_activity -> marketing_publication/asset/channel -> booking_inquiry -> booking_master -> finance_settlement -> marketing_attribution

守恒点：

- 草稿不能公开；过期或停用活动不能继续显示或发券。
- 每次发布保存版本、渠道、发布时间和操作人，不覆盖旧版本。
- 咨询、预订和收入通过不可变来源码关联，不能用活动名称猜归属。

## 三、数据库收口规则

1. 所有经营表都必须有明确 store_id；总经理跨店是权限，不是把 store_id 写成默认1。写入门店只从实时身份或已验证设备绑定取得。
2. 主单使用内部 bigint 主键，另有门店内唯一业务单号。外键统一引用内部主键，同时保存不可变来源单号供审计和打印。
3. 业务状态每张表只保留一个权威字段。booking_master 现有 booking_status/status、deposit/deposit_amount 必须明确权威列并迁移兼容，不能长期双写。
4. 取消和作废通过状态保留，不物理删除经营记录。桌台占用唯一约束必须只限制有效占用；不能让已取消历史阻止重新预订。
5. 原料 ID 全链统一 varchar(50)；库存数量三位小数，采购单价八位小数，货币两位小数。stock_take_detail 当前两位数量和旧 int 原料 ID 必须迁移收口。
6. 库存流水只保留一组权威变化量、前余额、后余额、来源和操作人。ingredient_inventory_log 现有 quantity/log_quantity、after_stock/stock_after、notes/note 等重复列必须明确淘汰顺序。
7. 应收、应付、支付、资金流水和凭证必须保存 source_type、source_id、source_no、request_id；关键来源加外键或可验证约束，request_id 建唯一键防重复。
8. 审批流绑定 business_type、business_id、business_no 和 document_version。审批人从实时登录身份取得，任何客户端提交的姓名只作显示输入，不能作授权依据。
9. 报表只从已落账业务表聚合，所有数字可点回来源单。接口异常必须返回失败，不能以空列表或旧缓存伪装成功。
10. 生产索引至少覆盖门店加日期、门店加状态、来源类型加来源主键、业务单号和 request_id；用真实查询计划验证，不只看索引是否存在。

## 四、页面怎样做到好用

### 今日工作台

首页按时间和责任显示“现在要做什么”：今日预订、待开台、厨房超时、待验收入库、低库存、盘点未完成、待审批、未结账和当日收支。每张卡直接进入对应单据，数字可回查，不放静态演示数据。

### 快捷录入

- 预订：手机号自动带客户，日期、餐段、人数筛出可用桌，三步内完成。
- 收货：先选供应商和采购单，支持扫码或键盘连续录数量、单价，实时显示金额和差异。
- 盘点：按厨房动线排序，回车进入下一行，支持单位换算、自动保存草稿和断网恢复。
- 收付款：先选来源单，再选账户与方式，页面实时显示已付、待付和本次后余额。
- 广告：选活动模板、图片、渠道、有效期，预览客人 H5 后提交审批与发布。

### 单据详情

统一显示基础信息、明细、金额或数量、审批时间线、执行流水、打印与来源去向。任何报表数字点击后能打开组成它的单据和明细。

### 打印

打印机、模板和规则必须来自后端真实配置并显示在线状态。页面不能硬编码示例 IP，也不能在未调用打印执行端时提示“发送成功”。无设备时允许预览和保存80mm PDF，并明确标记物理出纸未验证。

## 六、生产通过标准

只有在同一候选 HEAD 和同一制品上，六条业务链的真实浏览器、真实 HTTP、隔离 MySQL 回读、孤儿与跨店检查全部有精确数字；发布包逐文件可回退；生产三账号登录范围通过；法务保护清单未变化；发布后关键单据和报表可回查，才可以宣布餐饮系统达到生产可用。
